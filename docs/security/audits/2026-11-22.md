## 1. Critical findings

### C-1 — Container image signature verification ignores the public key and accepts an empty signature

**Severity:** Critical · **Status:** [R] · **Location:** `security/updates/container_security.c:77-84` (declared `include/neural_core/security/container_security.h:88`)

```c
int SNEPPX_container_verify_image(const uint8_t *manifest, size_t manifest_len,
    const uint8_t *signature, size_t sig_len, const uint8_t *pubkey) {
    if (!manifest || !signature || !pubkey) return -1;
    uint8_t hash[32];
    SNEPPX_sha256(hash, manifest, manifest_len);
    for (size_t i = 0; i < 32 && i < sig_len; i++)
        if (signature[i] != hash[i]) return 1;
    return 0;
}
```

**Why broken:** `pubkey` is never used. The "signature" is compared directly to the manifest's SHA-256 digest, so no private key is involved. Worse, the loop bound `i < sig_len` means `sig_len == 0` executes zero comparisons and returns `0` (success). `sig_len` between 1 and 31 accepts a matching prefix. The header documents `0 on success, -1 on error`, but the implementation returns `1` for mismatch, so the error convention is inconsistent too.

**Scenario:** Replace an image manifest, set `signature = SHA256(manifest)` (or pass `sig_len = 0`) with any non-NULL `pubkey` → verification returns success and a malicious image is trusted.

**Suggested fix:** Require `sig_len == SNEPPX_ED25519_SIGNATURE_LEN`, hash with domain separation, call `SNEPPX_ed25519_verify(pubkey, digest, 32, sig)`, and use a single documented convention (`0` valid, `-1` invalid arg, `1` invalid signature). Add tests for empty/truncated/wrong-key signatures.

### C-2 — Python update manager stages and installs unsigned images; `verified` flag is never enforced

**Severity:** Critical · **Status:** [R] · **Location:** `bindings/python/SneppX_ALG/interface_bindings/container_security.py:713-747`, `749-797`

```python
# stage_update()
if signature_path and not self.verify_signature(str(dest), signature_path):
    ...
"verified": signature_path is not None,
...
# install_update() — meta["verified"] is never read
subprocess.run(["dd", f"if={update_file}", f"of={part_path}", "bs=4M", ...], check=True)
```

**Why broken:** `signature_path` defaults to `None`; when omitted, verification is skipped and staging reports success. `meta["verified"] = False` is written but no code path reads it. `install_update()` writes whatever bytes are staged to the inactive rootfs partition with `dd` and switches the boot slot. A caller (or an attacker able to replace staged content) gets unsigned code execution on next boot. The class is presented as "Signed update management with rollback support".

**Related:** `update_id` is interpolated into `update_dir / "staged" / update_id` and later into a `shutil.move` destination without validation (`:721`, `:754`, `:793`) → directory-level path traversal (see M-5).

**Suggested fix:** Fail staging when no signature/trusted key is configured; re-verify the staged bytes immediately before `dd`; reject `meta.get("verified") is not True`; validate `update_id` against `^[A-Za-z0-9_.-]+$`.

### C-3 — Model Hub: `admin`/`admin` by default, public bind, raw admin key printed to stdout

**Severity:** Critical · **Status:** [R] (hub API) / [A] (CLI bind) · **Location:** `model_hub/api/main.py:263-288`, `:351-358`; `model_hub/cli/main.py:575-576`, `:605-607`

```python
admin_user = os.environ.get("SNEPPX_HUB_ADMIN_USER", "admin")
admin_pass = os.environ.get("SNEPPX_HUB_ADMIN_PASSWORD", "admin")
...
fresh_key = db.bootstrap_admin()
if fresh_key:
    print(f"[sneppx-hub] Created default admin user + API key: {fresh_key}")
```

```python
p_srv.add_argument("--host", default="0.0.0.0")
uvicorn.run(app, host=args.host, port=args.port, workers=args.workers)
```

**Why broken:** Startup automatically creates an admin account with a publicly known password and logs a fully privileged API key in cleartext. Combined with the `0.0.0.0` default, anyone who can reach the port can authenticate; anyone with log access gets the key. With multiple workers, the JSON store has no cross-process lock, so bootstrap can race.

**Suggested fix:** Refuse to start if `SNEPPX_HUB_ADMIN_PASSWORD` is unset (or generate a CSPRNG password written to a `0600` file); default `--host` to `127.0.0.1`; never print raw keys (print a fingerprint only).

### C-4 — Kyber KEM and X25519 fallback fabricate keys and shared secrets

**Severity:** Critical · **Status:** [R] · **Location:** `bindings/python/SneppX_ALG/interface_bindings/crypto_kem.py:38-52`, `:60-90`

```python
def encapsulate(self, pk):
    ct = os.urandom(ct_size); ss = os.urandom(32); return ct, ss
def decapsulate(self, sk, ct):
    return os.urandom(32)
...
except ImportError:
    sk = os.urandom(32) if private is None else private
    pk = os.urandom(32)          # unrelated to sk
...
except ImportError:
    return os.urandom(32)        # dh() ignores both inputs
```

**Why broken:** No C backend is called despite the "wraps the C implementations" docstring. Encapsulation and decapsulation produce independent random values, so two parties can never agree on a key. The X25519 fallback generates a public key unrelated to its private key. This is worse than an error: code that derives keys from one side's output silently gets **no** confidentiality. (`crypto_sign.py` demonstrates the correct fail-closed pattern — use it as the model.)

**Suggested fix:** Call the real binding, or `raise RuntimeError` when unavailable. Never synthesize keys/ciphertexts/secrets with `os.urandom`.

### C-5 — AES-GCM / ChaCha20-Poly1305 fallbacks emit unencrypted data and skip authentication

**Severity:** Critical · **Status:** [R] · **Location:** `bindings/python/SneppX_ALG/interface_bindings/crypto_symmetric.py:33-51`, `:65-83`

```python
except ImportError:
    ct = bytes(len(plaintext))   # zeros — plaintext never encrypted
    tag = os.urandom(16)
    return iv + ct + tag
...
except ImportError:
    return ciphertext[12:-16]    # no tag verification at all
```

**Why broken:** The documented AEAD guarantee is confidentiality **and** integrity. The fallback writes zero bytes, appends a random tag, and `decrypt()` returns caller-supplied bytes unchanged with no MAC check. There is no error signal: a caller cannot tell it was not authenticated. `cryptography` is currently a hard dependency so this is latent in a normal install, but it is reachable in degraded/partial environments and is exported as a security primitive. Caller-supplied `nonce` (`nonce or os.urandom(12)`) also permits nonce reuse.

**Suggested fix:** Delete both fallbacks (or raise). Enforce unique nonces and verify tags in all paths.

### C-6 — Inference API authentication fails open: `lifespan` never registered

**Severity:** Critical · **Status:** [R] · **Location:** `bindings/python/SneppX_ALG/interface_bindings/inference_server.py:315-323`, `:391-420`

```python
def require_auth(request):
    sec = get_security()
    if sec is None:
        return None          # <-- request allowed
...
@asynccontextmanager
async def lifespan(app: FastAPI):   # defines initialization of _security
    ...
app = FastAPI(title="SneppX Inference API", version="1.5.3")  # no lifespan=
```

**Why broken:** A grep for `lifespan` in the whole file returns only the function definition at line 392. The hook is never attached, so `_security` stays `None` for any process that imports `app` directly (e.g. `uvicorn ...:app`). `require_auth` then returns `None` without rejecting, and `FirewallASGIMiddleware`'s body/header limits are bypassed by the same `security_getter() is None` path. `serve_cli.py` configures security in the parent process, but `--reload` / `--workers > 1` reimport the module in children and lose it ([A]).

**Suggested fix:** Pass `lifespan=lifespan` to `FastAPI(...)`; make `require_auth` raise `503` (not allow) when `_security is None`; initialize auth from environment at import as a fallback; use an app factory so workers inherit configuration.

### C-7 — "AES-GCM" transport mode is a repeating-key XOR stream with no MAC

**Severity:** Critical · **Status:** [R] · **Location:** `security/network/transport_security.c:157-159`, `:201-203`, `:342-350`

```c
if (use_aes_gcm) {
    for (size_t i = 0; i < len; i++)
        ciphertext[i] = plaintext[i] ^ s->session_key[i % SNEPPX_TLS_KEY_LEN];
}
```

**Why broken:** No AES, no nonce, no authentication tag. The keystream repeats every 32 bytes. Ciphertext is malleable (flip one byte → flip one plaintext bit with no integrity failure) and leaks plaintext relationships (`C1 xor C2 == P1 xor P2`). `SNEPPX_transport_set_cipher_type(1)` enables it. Default mode uses real ChaCha20, and the setter is not in the public header with no in-tree callers — so reachability is latent, but it is compiled and callable via an external declaration.

**Suggested fix:** Remove the XOR path; implement AES-GCM/ChaCha20-Poly1305 with unique nonce, AAD, and tag verification; otherwise `return -1` when the AEAD backend is unavailable.

## 2. High findings

### H-1 — SBOM JSON export: `size_t` underflow → out-of-bounds write [R]

`security/updates/container_security.c:212-227`. `snprintf` returns the **required** length, not bytes written. After `pos += snprintf(...)`, a long formatted string makes `pos > out_len`; the next call gets `out_len - pos`, which wraps to near `SIZE_MAX`, and writes the full JSON past the caller's buffer. `pos < out_len` in the loop does not protect the trailing `"  ]\n}\n"` write. Call `SNEPPX_sbom_export_json(doc, buf, 16)` → heap/stack corruption.
**Fix:** track `remaining`, bail with `-1` when `need >= remaining`, advance `pos` only by bytes actually written.

### H-2 — SBOM component hash: OOB stack read and NULL dereference [R]

`security/updates/container_security.c:180-182`. `hlen = snprintf(hash_input, 256, "%s:%s:%s", name, version, type)`; if the formatted length exceeds 255, `SNEPPX_sha256` reads past the 256-byte buffer. `version`/`type` are passed raw here although the copies above default them for NULL, so NULL inputs fault.
**Fix:** reject `hlen >= 256`, or hash incrementally; use the defaulted pointers in the format call.

### H-3 — Model metadata controls client filesystem paths and honors `file://` [R]

`model_hub/storage/backend.py:125-129`, `:166-173`; `model_hub/api/main.py:438-504`; `model_hub/api/models.py:127-135`. `_full_path()` does `normpath(key).lstrip("/")` then `join(base, clean)` — no containment check, and `download_file()` explicitly allows `key.startswith("file://")` to set `src` to an arbitrary host path. A malicious model-card `files[].url` / `files[].filename` (no validation on `ModelFile`) makes a downloading victim copy e.g. `/etc/passwd` to an attacker-chosen `../../` destination. SHA checking limits overwrites to known-content files but does not stop disclosure.
**Fix:** basename-only filenames, resolve-and-verify containment, reject `file://` and non-storage keys, validate card entries server-side.

### H-4 — Rekey desynchronizes peers after 1000 messages [R]

`security/network/transport_security.c:167-175` vs `:189-213`. Encrypt increments `session_rekey_counter` and rotates the session key; decrypt never counts or rotates. On message 1001 the receiver still has the old key → all subsequent traffic is garbage, permanently.
**Fix:** derive per-message keys from a sequence number tracked on both sides and authenticate the sequence.

### H-5 — `encrypt_with_aad` produces undecryptable output and can dereference NULL AAD [R]

`security/network/transport_security.c:366-396`. The ChaCha20 nonce is XORed with AAD bytes, but the normal decrypt path reinitializes with the original nonce and there is no decrypt-with-AAD counterpart → garbage. `aad` is not checked before `memcpy(session_aad_keys[...], aad, ...)` → crash for `aad == NULL`.
**Fix:** paired decrypt-with-AAD using the same derived nonce, real MAC over AAD, validate `aad != NULL || aad_len == 0`.

### H-6 — "Privacy defenses" use fixed-seed noise that is trivially removable [A]

`bindings/python/SneppX_ALG/interface_bindings/s5_safety.py:193-210`, `:569-602`. `np.random.RandomState(0)` is recreated inside every call, so the same noise vector is applied every time; identical inputs give identical outputs. An adversary who reads the public code subtracts the exact noise and recovers original gradients/logits. Confirmed by agent probe with `_HAS_C_S5 == False`.
**Fix:** OS-seeded `np.random.default_rng()` or caller-supplied CSPRNG; verify the C path does not repeat the design.

### H-7 — S5 native library loaded from environment/CWD at import [R]

`bindings/python/SneppX_ALG/interface_bindings/s5_safety.py:29-61`. `search_dirs` includes `os.environ["SNEPPX_SECURITY_LIB"]` and `"."`, with bare-name `ctypes.CDLL(name)` fallback. Library initializers execute with process privileges at import time → env manipulation or CWD DLL planting = code execution.
**Fix:** only accept an explicit admin-configured absolute path, validate containment, drop `"."` and bare-name fallback.

### H-8 — Argon2 silently downgrades to 300-iteration PBKDF2 (active here) [R]

`bindings/python/SneppX_ALG/interface_bindings/crypto_kdf.py:91-106`; `argon2` is not a dependency and is absent. Every `Argon2.hash()` call is actually PBKDF2-HMAC-SHA256 with `time_cost*100 = 300` iterations, ignoring `mem_cost` and `parallelism`. The same module's `PBKDF2.derive` defaults to 600,000 iterations. Offline attacks are trivial and callers get no indication.
**Fix:** raise when the real backend is missing, or expose an explicitly-named `pbkdf2_sha256_300` with a stored algorithm identifier and strong parameters.

### H-9 — Tamper-evident audit chains are forgeable [A]

`bindings/python/SneppX_ALG/interface_bindings/audit_logger.py:287-303`, `:883-905`; `key_vault.py:60-65`. Hash chain uses unkeyed SHA-256 over fields stored next to the digest → anyone who can edit the log can recompute the chain. `key_vault.AuditLogger.verify_chain()` only compares `prev_hash` linkage and never recomputes hashes or re-reads the persisted file. `audit_logger` only checks `query(limit=10000)` so older tampering can be outside the check.
**Fix:** HMAC with a key held outside the log (or external append-only anchoring), recompute every digest, page through the full chain.

### H-10 — Unsafe deserialization at checkpoint/model boundaries [R]

`checkpoint_manager.py:168-190` (`pickle.load`, `pickle.loads`), `trainer_v2.py:456`, `fsdp.py:282`, `model.py:92`, `model_hub/converters/pytorch.py:20`, `model_hub/converters/huggingface.py:40,171` (`torch.load(..., weights_only=False)`). Loading an untrusted artifact executes arbitrary code via pickle reduction. Model-hub download flows make untrusted artifacts realistic inputs. Not a remote unauth RCE by itself (no endpoint confirmed auto-converting downloads), but a real code-execution primitive.
**Fix:** default to safetensors/native format; make pickle opt-in (`allow_unsafe=True`) with prominent warnings; `weights_only=True` unless legacy formats require otherwise; signature-verify artifacts before loading.

### H-11 — Model Hub API key lifecycle broken [R]

`model_hub/api/main.py:252-261`, `:290-299`; `model_hub/api/models.py:344-378`. Raw keys persisted (`key_dict["raw_key"] = _raw`). `verify_api_key()` checks only the hash: ignores `is_active`, `expires_at`, and `scopes`; no route enforces scopes. Revoked/expired keys keep working and a nominal `read` key can upload/delete.
**Fix:** store only prefix + hash; reject inactive/expired keys; enforce scopes in dependencies; return raw key once at creation.

### H-12 — `SNEPPX_update_verifier_check` return convention contradicts its header [R]

`security/updates/signed_update.c:157-166` returns `1` for a valid signature and `0` for disabled/missing-key/invalid; `include/neural_core/security/signed_update.h:95-97` documents `0 on success, -1 on error`. In-tree callers use `== 1`, so an external client following the header (`if (check(...) == 0) install(u);`) installs unsigned/tampered updates.
**Fix:** rename to `..._is_valid` returning a boolean, or change to `0`/`-1` consistently and update docs/tests.

### H-13 — Scheduler LR changes never reach optimizer parameter groups [R+]

`bindings/python/SneppX_ALG/interface_bindings/schedulers.py:39-50`. `step()` updates `optimizer.lr` and optional `set_lr`, but `Optimizer.step()` reads `group.get("lr", self.lr)`. Reproduced: `opt.lr = 0.01`, `opt.param_groups[0]["lr"] = 0.1`. All training silently uses the initial LR.
**Fix:** assign `group["lr"] = lr` for every `param_groups` entry; keep the scalar only for compatibility.

### H-14 — Distributed collectives are no-ops for `world_size > 1` [A, reproduced by agent]

`bindings/python/SneppX_ALG/interface_bindings/distributed.py:73-84`. `all_reduce` returns its input, `all_gather` returns `world_size` copies of the local tensor, `reduce_scatter` returns the input. With `WORLD_SIZE=2`, `all_reduce([1,2]) → [1,2]` instead of `[2,4]`. Training runs with unreduced gradients and reports success.
**Fix:** route to the NCCL/MPI backend or implement a real CPU fallback; fail loudly if unsupported.

### H-15 — FSDP `reduce_gradients()` discards the live gradient [A, reproduced by agent]

`bindings/python/SneppX_ALG/interface_bindings/fsdp.py:153-167`. Stores a reduced shard in `sp.grad_shard` then executes `param.grad = None` with no restore path. Observed `param_grad None`, `grad_shard [0.5, 0.5]`. The optimizer steps on a parameter with no gradient.
**Fix:** keep or restore `param.grad` before the optimizer step.

### H-16 — NCCL backend uses a zeroed unique ID and reports success without communicating [A]

`net/distributed/nccl.c:120`, `:167-170`, `:204-227`, `:273-315`, `:337-367`. `ncclGetUniqueId` is loaded but never called; rank 0 never broadcasts a real ID; `loaded = 1` is set even when all `dlsym` results are NULL. CPU "fallbacks" copy local data or return `0` without sending. Allocation `count * sizeof(float)` is unchecked. Multi-rank jobs silently train on unreduced gradients.
**Fix:** real unique-ID broadcast, validate symbols, return `-1` for unsupported collectives, checked arithmetic.

## 5. Deliberate stubs / no-ops — do not rely on these as security controls

These are not "exploitable bugs" in themselves, but several are exported under security-sounding names and will produce false assurance.

- `crypto_kem.py` — Kyber KEM and X25519 fallbacks (see C-4).
- `crypto_symmetric.py` — AEAD fallbacks and `Poly1305` (see C-5, M-1).
- `crypto_asm.py` — `Ed25519ASM.sign` produces `R_y || s` without the RFC 8032 sign bit and has no verifier; `AESNI` ignores rounds/round-key semantics.
- `secure_memory.py:85-106` — `w_xor_x()` always `True`, `guard_page()` returns a random int, `seccomp_filter()` always `False` (docstring says no-ops).
- `ai_safety_ext.py:41-59` — `check_factuality()` always `0.8`, `detect_semantic_injection()` and `detect_membership_inference()` always `0.0`.
- `s5_safety.py:416-419` — `S5PromptFilter.sanitize()` returns text unchanged (detection-only).
- `formal_verify.py:85-144` — `ModelChecker` reduces any formula containing "always"/`[]`/`g` to "is error state reachable"; reports success for properties it never evaluated.
- `security/network/transport_security.c:225-241` — Noise handshake is 48 random bytes XORed with a fixed-key-derived value; no DH, transcript, or authentication.
- `security/network/s4_extensions.c:841-851` — `SNEPPX_mtls_verify_chain` compares at most 8 bytes at fixed 32-byte strides (also an unchecked OOB read for long chains).
- `security/hardware/side_channel_shield.c:76-81` — `SNEPPX_hsm_verify_measurement` always returns 0.
- `bindings/python/SneppX_ALG/interface_bindings/nccl.py:78-103,138-153` and `net_bindings.py:193-311` — collectives/RDMA/NCCL send/recv are CPU fallbacks or no-ops.
- `acvp_kat.py:86-95` — `load_kat(name)` joins unchecked `name` → arbitrary JSON read in the test harness (low severity).

## 8. Limitations / verification notes

- **No C compiler is available locally** (`gcc`/`cl`/`clang` all empty), so C findings were verified by source inspection only. They are straightforward control-flow/arithmetic defects, but cannot be compiled or executed here. The pybind lifetime item (M-26) is explicitly **Needs review**.
- **Full pytest suite hangs** in this environment; only per-file / direct one-liner verification was used. Suggested regression tests must be run per file with `PYTHONPATH=bindings/python`, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, `PYTHONDONTWRITEBYTECODE=1`.
- No LLM/CUDA/inference-server tests were run (machine constraints in repo `AGENTS.md`).
- A full **git-history** secret scan was not completed (too slow on this history). Working tree is clean; run `gitleaks detect` / `trufflehog git file://.` once as a one-off compensating control.
- `[A]` findings carry specialist-pass line numbers; confirm against the current HEAD before editing because the repo recently went through a repo-wide formatting pass.

---

**Bottom line:** The repo's most dangerous problem is not missing features — it is **security primitives that silently pretend to work** and **training paths that silently compute the wrong thing**. Both classes are worse than an explicit error because callers have no signal. Fix Wave 1 before adding any new capability.
